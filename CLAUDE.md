# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

BSW Kota Bogor multi-camera traffic intelligence dashboard: YOLOv8 (CoreML on the Apple Neural Engine) + ByteTrack over the city's municipal HLS CCTV feeds, citywide vehicle counting and congestion analytics, FastAPI backend + Leaflet frontend. Engine (`car_tracker/`) and dashboard (`backend/`, `frontend/`) live in this one repo.

**Stale docs:** `HANDOFF.md`, `TEST_INFRA.md`, `TEST_READY.md`, `.agents/` are old notes written for a previous two-folder layout (`teamwork_projects/...`). Do not trust their paths, test counts, or the license-plate (LPR/TNKB) rules — **the plate-recognition feature was intentionally removed** (backend endpoints, overlays and frontend included); vehicles are labelled by class only, and no track/vehicle ids are drawn on video frames.

## Commands

Always use the project venv (Python 3.11, macOS/Apple Silicon required for CoreML):

```bash
./start.sh                                   # run server at http://127.0.0.1:8000 (kills whatever holds :8000)
.venv/bin/python3.11 -m pytest -q            # full suite (testpaths=tests, offline, no network)
.venv/bin/python3.11 -m pytest tests/test_rolling_tracker.py -q
.venv/bin/python3.11 -m pytest tests/test_rolling_tracker.py::test_name -q   # single test
.venv/bin/python3.11 scrape_cctv_streams.py  # re-scrape bsw.kotabogor.go.id; syncs topology JSON + DB
```

`scripts/start_daemon.sh` / `stop_daemon.sh` run uvicorn under `caffeinate`. The scripts find the server with `lsof -ti tcp:8000 -sTCP:LISTEN` and wait for it to exit — a plain `lsof -ti :8000` also lists connected browser tabs (the kill then failed silently, or `start.sh`'s `kill -9` hit the browser). Both start scripts bind `HOST=0.0.0.0` (LAN; `HOST=127.0.0.1` for local only — the dashboard has no auth). `test_f_arch_02` (latency) is timing-flaky under load. `tests/conftest.py` redirects every writable data file (`TRAFFIC_DB_PATH`, `ANALYTICS_DB_PATH`, `COUNTING_LINES_PATH`, `FREE_FLOW_PATH`) to a temp dir, so the suite is safe to run while the live server is up — keep it that way.

```bash
.venv/bin/python3.11 scripts/export_dataset.py --start 2026-10-11 --end 2026-10-12 --bucket 15 --format csv --raw all   # analysis export -> data/exports/
```

## Architecture

**Request/inference flow.** `backend/server.py` (FastAPI, ~840 lines) is a thin layer: REST + `/ws/live` + frame endpoints. All inference is done by `backend/rolling_tracker.py` (`RollingTracker`, a single inference worker thread) — the server only renders annotated frames (`_render_annotated_frame`) from what the tracker hands back. `backend/indexing_daemon.py` (`IndexingDaemon`) is **not used by the server any more** (class and tests kept); `/api/daemon/*` controls the rolling tracker.

**Rolling tracker model.**
- *Focus cameras*: cameras currently being viewed (`set_focus` is called on every frame-endpoint poll; lapses after `FOCUS_TTL_S`), up to `MAX_FOCUS_CAMERAS`, run at `FOCUS_FPS`. A slot is only reclaimed from a viewer idle for `FOCUS_EVICT_IDLE_S`; otherwise `set_focus` refuses (returns False → "viewer limit" frame) — evicting on every poll made N+1 viewers thrash each other forever. `tick()` serves due focus cameras between rolling-visit frames (most overdue visit first).
- *Rolling visits*: remaining stream slots (`MAX_OPEN_STREAMS`, default 12, at most `MAX_STREAMS_PER_HOST`=3 per restreamer host — the 96 cameras sit on 6 hosts, and an overloaded host refuses connections and gets backed off wholesale) visit every other camera for a dwell time by tier (tier1 = downstream of a focus camera, tier2 = arterial hubs, tier3 = LRU) at `ROLLING_FPS`, so vehicles are counted citywide. Tunables are env-overridable in `backend/config.py` (`ROLLING_*`, `ROLLING_ENABLED=0` → focus only). Optional standby slots (`ROLLING_STANDBY_SLOTS`, default 0) pre-open the next visits' streams; off because a simulation showed they cost more coverage (−11% camera-s/s at 2) than the ~8% connecting time they save.
- `StreamPool` opens/releases HLS captures off the inference thread (`backend/stream_capture.py`, `ThreadedStreamCapture`). Never open streams on the inference thread. Dead cameras/hosts get escalating jittered backoff.
- A track becomes one `vehicle_sightings` row after `MIN_TRACK_HITS` frames; parked vehicles are re-matched by class + IoU on the next visit so they aren't recounted.

**Congestion index (`car_tracker/analytics.py`).** Judged only on the *traffic stream*: each track is "traffic" (has moved ≥0.6 body sizes since first seen), "queued" (still, but standing where moving traffic drives, after `QUEUE_AFTER_S`=2 s), "parked" (still for `static_after_s`=6 s and *not* in a lane) or "undetermined" (young and still). Where traffic drives is a per-camera **lane map** (`_LaneMap`): a decaying heat map, on the 48×27 coverage grid, of the ground footprints (lower half of the box) of moving vehicles, persisted in `data/traffic_lanes.npz`; a still vehicle whose footprint scores ≥`LANE_MIN_SCORE` is queued. Until a camera has `LANE_MIN_OBS` moving footprints (~45 s watched) the old rule applies (still ≥6 s → parked). Why both: excluding parked cars fixed a car park reading as a permanent jam (camera 167), but judging "parked" by "hasn't moved yet" alone called most of a stop-and-go queue parked and rated a jammed junction "Smooth" (camera 168, 2026-10-12: 11 of 16 queued vehicles "parked"). All distances/speeds are in *body sizes* (box size) per second, so they are comparable near/far and across cameras; never reintroduce fixed px/s thresholds. Index = 0.40·queue (share of the stream standing still, full at 50%) + 0.45·slowness (median speed vs the camera's *own* free-flow speed = p85 of its traffic speeds, persisted in `data/free_flow_speeds.json`; it rises fast (0.2) on faster windows and sinks slowly (0.01), so a usually-jammed camera can't learn its jam as "free flow"; until learned only a full standstill counts) + 0.15·density·slowness (`lane_occupancy` = share of the learned lane area covered by stream footprints, full at 45%; frame coverage until lanes are learned), damped quadratically below 6 measurable vehicles. Live value = mean of the last 20 s of per-frame values; window value = mean over the window (windows also store `lane_occupancy`). Labels (backend `get_congestion_label`, mirrored in `app.js`): <0.25 Smooth, <0.55 Moderate, <0.8 Heavy, else Congested. Known limits: red-light stops read as queueing; a vehicle parked inside a lane reads as queued; analytics window `total_volume` still counts track ids (inflated by track fragmentation) — counting-line rates are the reliable volume.

**Analytics volume = counting-line crossings.** The rolling tracker marks each detection record `counted_now` (that track crossed the camera's counting line in this frame); when the key is present, the engine builds window volume/class volume from those crossings, so `camera_traffic_timeseries.total_volume` matches `observation_windows` (the older track-id volume was inflated ~10× by track fragmentation). Rows carry `volume_basis` (`crossings` | `tracks`; the live DB's track-based rows were purged on 2026-10-11, so it only holds `crossings`) — never mix the two in one series. The server builds the engine with `assume_crossings=True`, so empty windows are labelled `crossings` too; callers that don't send `counted_now` (tests, standalone CLI) keep track-based volume. Time features (`hour`, `day_of_week`, `is_weekend`) are WIB (Asia/Jakarta); `timestamp_iso` stays UTC next to `timestamp_local_iso`. `query_timeseries(window_seconds=N)` aggregates the 2–62 s rolling windows into N-second buckets (it used to filter `window_seconds=60`, which matched ~1% of rows). The Analytics tab reads `/api/cameras/{id}/metrics` → `flow`: hourly rate from `db.get_camera_rates`, per-bucket series from `db.get_camera_flow_series` (epoch-aligned buckets, unobserved buckets omitted → chart line breaks) joined with `analytics.get_congestion_series` (length-weighted). Params `minutes` (≤1440), `bucket_minutes`.

**Throughput.** `car_tracker.CoreMLDetector` calls the CoreML NMS-pipeline export directly (cv2 letterbox → PIL → `MLModel.predict`). Ultralytics' predictor cost 4–7 ms of GIL-holding CPU per frame in its CoreML backend — the old "~40 fps ANE ceiling" was mostly that, not the ANE. 16:9 frames use `yolov8m_384x640.mlpackage` (`WIDE_MODEL_PATH`; same detections, ~40% less ANE time); 704×576 cameras keep the 640×640 model (the wide one loses ~22% of their detections). detect() is ~3.7 ms per 720p frame (was ~10 ms); a live run processed ~75 fps with all 11 visits observing. Rejected after measuring: yolov8n (finds ~33% of yolov8m's vehicles), batched/dynamic exports (fall off the ANE), a second inference thread (ANE serialises requests), `sys.setswitchinterval`.

**Stream capture.** No `fflags;nobuffer` (it made the first frame wait a full GOP, median 3.2 s). `ThreadedStreamCapture` plays live streams out in real time against `CAP_PROP_POS_MSEC` (HLS delivers whole segments at once; wall-clock pacing below the source fps played rolling visits at ~0.75× and read rates/speeds ~25% low), runs ~1 segment behind live, converts only frames due at `max_fps` (re-read every frame), and uses one decoder thread. `StreamPool` releases captures on a separate executor and judges "slow" opens before releasing.

**Engine (`car_tracker/`)**: `ANEVehicleDetector.detect(frame, camera_id=...)` does per-camera ByteTrack state (`detector.reset_tracks(cid)` at visit end); `analytics.py` is `TrafficAnalyticsEngine` (time-series windows → `data/traffic_timeseries.db`). `backend/detector.py` is the shared ANE model loader. `backend/config.py` `ENGINE_ROOT` defaults to the project root (override `CCTV_YOLO_ANE_ROOT`) and `ensure_engine_importable()` puts it on `sys.path`.

**Volume vs sightings (two separate pipelines).** *Traffic volume* comes from `backend/counting.py`: a learned counting line per camera (`data/counting_lines.json`; "passage" mode until 12 trajectories), crossings recorded in `observation_windows` with observed seconds, rates via `db.get_camera_rates()` → `/api/cameras/counts` (`camera_rates`, `citywide_vph` — one camera per junction cluster). Rates from <60 s observation are flagged `low_sample`. `TrackCounter` counts a track only when its start and current points lie on opposite sides of the *current* line and it moved ≥3% of the frame (a line refit mid-visit used to count a queued car that never moved). *Sightings* feed the Recent tab, sighting totals and raw exports, not volume.

**Topology (no re-identification).** `backend/topology_engine.py` loads `data/bogor_camera_topology.json` (camera nodes + directed edges, one-way enforcement, arrival windows [t_min, t_max]); the tracker uses it for tier-1 scheduling (cameras downstream of a focus camera) and the server for junction clusters. **Cross-camera re-identification ("Follow That Car": global vehicle ids, appearance embeddings, handoff events, active targets, journeys, follow mode) was intentionally removed** — backend, endpoints, schema and frontend; `migrate_schema` (`_drop_reid_schema`) drops its tables/columns from older databases on open. Don't reintroduce it.

**Persistence.** `backend/database.py`: SQLite WAL at `data/traffic_db.sqlite`. **Every write must go through `database._transaction()`** (commit/rollback) and never be wrapped in a bare `except: pass` — a swallowed FK error previously left a transaction (write lock) open forever and froze the tracker. Debug hangs by dumping `sys._current_frames()` in-process (py-spy absent; macOS `sample` shows no Python frames).

**Dashboard stats path (keep it off the event loop and off full-table scans).** All-time totals come from trigger-maintained tables (`sighting_totals`, `sighting_tracks`, `camera_track_totals`, `sighting_counters`; an AFTER INSERT trigger on `vehicle_sightings`, created and backfilled once by `migrate_schema`, marker `totals_v1`) — they count inserts, so retention never lowers them; `rebuild_totals()` is a repair tool (resets to what is still stored). The old covering indexes `idx_sightings_agg` / `idx_sightings_local_track` were dropped (nothing used them after the switch). Windowed counts read `idx_sightings_cam_time`. `db.search_sightings` (indexed: camera id, class, camera name/corridor) has no endpoint at the moment. Dashboard aggregates go through `server._stats_cache` (`_TTLCache`, `STATS_CACHE_TTL_S`=3 s, one computation shared by all tabs; cached values are shared, never mutate them). The `/ws/live` heartbeat builds its payload in `asyncio.to_thread` and carries `counts` + `recent`, so the frontend applies them directly (`applyStats`) instead of refetching. Sightings carry no blobs any more (older versions stored appearance blobs, which grew the file ~800 MB/day). Server startup runs `db.compact()` once per database (marker `compacted_v1`): switches to `auto_vacuum=INCREMENTAL` and VACUUMs (live DB 70.5 → 25.6 MB on 2026-10-12; pre-migration backup in `data/backups/`). `backend/maintenance.py` passes: opt-in retention (`SIGHTING_RETENTION_DAYS`, default 0 = keep forever; sightings, batched; observation_windows are never deleted) → `incremental_vacuum` → `PRAGMA optimize`. Per-thread connections are closed when their thread ends (`_ThreadConnection`).

**Data export for analysis (`backend/dataset.py`).** `build_dataset(start, end, bucket_minutes, camera_ids, fill_gaps, layout=long|wide)` streams a tidy per-camera time series: fixed buckets aligned to WIB wall clock, counting-line crossings and observed seconds prorated by overlap (Σ matches `observation_windows` exactly), vph overall/per class/per direction, coverage_ratio + `low_sample`, length-weighted congestion/speed/occupancy from the analytics DB, local time features with sin/cos encodings; `fill_gaps` emits unobserved buckets as nulls for sequence models. `iter_raw` exports raw tables (never blob columns; `*_local` WIB column next to each UTC time). Both DBs are opened read-only. Endpoints: `/api/export/dataset`, `/api/export/raw?table=`, `/api/export/dictionary` (CSV/JSONL, streamed, ≤31 days; the Analytics tab has an Export panel). CLI `scripts/export_dataset.py` adds Parquet (needs pyarrow, not installed), npz sequence tensors (`--seq-len/--horizon/--target`), `dictionary.json` + `provenance.json`. Coverage caveat for analysts: each camera is observed only during visits (mean coverage ~12% of a 15-min bucket when observed) — weight or filter by `observed_s`.

**Frontend** (`frontend/index.html`, `app.js`, no build step): Leaflet map + HUD. Video is a long-poll of `/api/stream/{id}/frame?after=<X-Frame-No>` (one request in flight per tab; the server waits ≤1 s for a newer frame, else 204; `frame_no` is the tracker's global counter, not the capture seq) rather than MJPEG/WebSocket video, because MJPEG stalls in Safari/WebKit. Polling stops while the tab is hidden (it would otherwise hold a focus slot). Frames are downscaled to ≤1280 px wide before JPEG encoding.

## Gotchas

- CoreML models are not thread-safe for concurrent forward passes; inference goes through the single detector path/lock — don't add new threads that call the model directly.
- `cctv_streams.json` at root and `data/cctv_streams.{json,csv}` are scrape outputs; the dashboard reads the topology JSON + DB, not `cctv_streams.json`. Camera/edge totals in tests are derived from the topology file (`tests/__init__.py`), not hardcoded.
- Model weights (`*.pt`, `*.mlpackage`) are gitignored; export with `yolo export model=yolov8m.pt format=coreml nms=True` (→ `yolov8m.mlpackage`) and `... imgsz=384,640 nms=True` renamed to `yolov8m_384x640.mlpackage`. The direct CoreML path needs the NMS outputs (`confidence`/`coordinates`).
- Without a loadable model the production detector returns no detections (retrying the load every 60 s; `/api/daemon/status` → `model_loaded`); the synthetic detector is test-mode only.
- Streams come from municipal restreamers with connection limits and flaky cameras; keep FFmpeg/OpenCV quieted (`OPENCV_LOG_LEVEL=ERROR`, `OPENCV_FFMPEG_LOGLEVEL=8`, set in `start.sh`) and `ulimit -n` raised to avoid Errno 24.
